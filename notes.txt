here is the overview it gave me for roblox script executors.
1. Process Memory Injection
Before interacting with Luau, the executor must break into the Roblox process (RobloxPlayerBeta.exe).
User-Mode / Driver Injection: The executor application uses memory allocation APIs (VirtualAllocEx, WriteProcessMemory) or kernel-mode drivers to map a Dynamic Link Library (DLL) into Roblox’s address space.
Execution Hijacking: By spawning a thread (CreateRemoteThread) or hooking an existing thread inside the game process, the injected DLL gains the ability to execute C/C++ code directly inside Roblox's memory space.
2. Locating the Luau State (lua_State)
Once executing inside Roblox's memory, the injected DLL must find where the game engine stores its scripting engine.
Pattern Scanning (AOB): The DLL scans Roblox's memory for specific byte sequences (signatures) to locate internal functions and global pointers.
lua_State Retrieval: It identifies the lua_State structure pointer, which holds the active execution stack, global variables, garbage collector state, and registered C functions.
3. Escalating Script Security Identity (Capabilities)
Roblox isolates code using Security Identities (Levels 1 through 8). Normal game local scripts run at Level 2, preventing them from modifying critical game data or calling restricted functions.
Memory Patching: The injected DLL accesses the ExtraSpace or userdata offset linked to the active lua_State thread.
Capability Privilege Elevation: It directly overwrites the thread's permission bitmask, upgrading the script's identity to Level 7 or 8 (CoreScript / Plugin level). This grants the thread unrestricted permission to invoke methods like game:GetService("CoreGui") or access internal engine objects.
4. Bytecode Compilation and Loading
The Luau Virtual Machine does not execute raw text strings directly; it only reads binary bytecode.
Luau Compiler: The executor's UI takes the user's custom script text and compiles it into Luau bytecode formatted specifically for Roblox's modified opcode structure.  
Passing to the Loader: The injected DLL invokes Roblox's internal bytecode loading function (e.g., luau_load or luavm::load) directly from process memory. This converts the compiled bytecode buffer into a callable Luau closure (Closure*) inside the VM.
5. Task Scheduler Integration
Running foreign code from an unmanaged thread would cause memory corruption or instant game crashes due to race conditions with Roblox's render and physics loops.
Thread Creation: The DLL calls lua_newthread / luaL_sandboxthread to allocate a safe, isolated thread from the global lua_State.
Scheduling: The closure is pushed onto Roblox's internal Task Scheduler queue. The main game loop then executes the injected script safely on the next frame update alongside regular client scripts.
6. Environment Augmentation & Metamethod Detouring
To expand what the injected scripts can do, the executor modifies the script's global environment (getfenv).
Injecting Custom APIs: The DLL registers custom C functions into the global table, providing script authors with extra utilities like getgenv(), decompile(), firetouchinterest(), and request().
Metatable Hooking: The executor hooks into the engine's central metatable methods (such as __namecall or __index). This allows injected scripts to intercept, block, or rewrite network traffic and RemoteEvent calls before they reach Roblox's network layer.
